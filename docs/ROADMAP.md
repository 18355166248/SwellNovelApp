# 轻读迭代计划

本计划按本地优先、数据安全和三端可维护性排序。每个阶段完成后均应通过
`npm run check`，并在 iOS、Android、Web 上完成对应的回归验证。

## 阶段一：稳定性与减负

目标：让已有阅读数据可靠保存，日常开发和 Web 加载保持可控。

- 元数据与正文改为原子写入，启动时检测损坏并从最近一次备份恢复。
- 增加全局 Error Boundary，提供可理解的恢复入口。
- 为 10 MB 与 50 MB TXT 导入、分页、恢复位置建立性能基准。
- 拆分 ReaderScreen、useOnlineBook 与 bookshuku，保持核心交互测试覆盖。
- 为 Web 图标字体做按需子集化，目标减少至少 250 KiB 首次下载资源。
- 继续保持构建产物、依赖目录和临时文件不进入源码检查与 Git 历史。

验收：数据写入失败不丢失已有书库；TypeScript、Lint、Jest 和 Web 生产构建全绿。

## 阶段二：数据安全与管理

目标：用户可以自主带走、恢复和管理本地数据。

- 实现书库备份、恢复与导出，包含书籍元数据、正文、进度、书签、设置和统计。
- 使用带版本号与校验和的压缩归档，恢复前预览并支持冲突处理。
- 增加在线章节缓存与下载字体的占用展示、一键清理和下载进度/取消。

验收：在不同设备或清空 App 后可完整恢复书库与续读位置；损坏备份不会覆盖现有数据。

## 阶段三：深度阅读

目标：增强长期阅读和内容回顾体验，不依赖账户系统。

- 在选中文本上提供划线、颜色标记、笔记与摘录导出。
- 增加阅读目标、周/月趋势和阅读日历，复用现有每日阅读时长数据。
- 支持 EPUB 导入，先覆盖常见无 DRM 的纯文本 EPUB，再逐步补充样式处理。

验收：标注能在翻页、字体调整和重启后准确定位；EPUB 导入失败时提供明确原因并不影响书库。

## 阶段四：联网与大屏

目标：在不降低本地阅读可靠性的前提下增强在线能力。

- 将生产书源代理迁移到 HTTPS，关闭 iOS 的全局 ATS 例外。
- 增加书源健康检查、失败降级与用户可配置书源管理。
- 提供用户主动开启的跨设备同步；没有同步服务时不展示误导性的状态。
- 优化平板双栏布局，并评估系统 TTS 语音朗读。

验收：在线书源异常不会影响本地书籍；同步冲突可见、可恢复且不静默覆盖数据。
