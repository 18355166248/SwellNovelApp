# iOS 搜书、入库与阅读优化验收

日期：2026-10-03。目标平台：iOS。设备：iPhone 17 Pro 模拟器，iOS 26.2，Xcode 26.2，Debug/arm64。未提交 Git。

## 问题与修复

| 方向      | 原问题                                                                    | 当前处理                                                                                             |
| --------- | ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 搜书      | 原生/Web 解析不同；镜像域名漏搜；空格、书名号影响匹配；单个慢源阻塞结果   | 统一解析、登记根域搜索、标准化书名与作者、排序去重；并发分批展示；单次引擎和目录兜底均设等待上限     |
| 搜书      | 精确已知书名只显示固定入口，入口失效后缺少其他源                          | 固定候选先显示，继续检索其他登记书源；输入变化后取消旧结果发布                                       |
| 加书      | 连点重复入库；目录保存失败仍显示成功；重复识别损失阅读数据                | 同书请求合并，保存成功才发布；保留正文缓存、章节身份、书签、续读和追更；识别短目录时保留完整本地目录 |
| 加书      | 代理、WebView、镜像回退累加导致长时间“添加中”                             | 解析阶段总上限 45 秒；迟到解析不能偷偷发布入库；明智屋长目录最多三路并发，按原顺序合并               |
| 缓存      | 子页循环、短尾页、保存失败造成不完整正文被标成已缓存                      | 子页循环保护；尾页单独校验；只统计完整且当前版本有效缓存；保存失败明确报错并支持重试                 |
| 本地导入  | iOS Hermes 缺少 TextDecoder 时有效 TXT 被读成空正文                       | 字节级 UTF-8/UTF-16 解码，覆盖中文、扩展字符、表情；不支持的编码提示转换 UTF-8，避免空书或乱码       |
| 书架/存储 | 最后一次进度和入库可能被后台防抖丢失；同文件写入乱序                      | 后台/退出读取实时 store 保存；同文件串行写；新书和最近阅读优先                                       |
| 阅读      | 旧滚动测量/延迟回调覆盖新章；退出前最后位置丢失；续载失败重试仍命中旧缓存 | 测量和回调绑定当前阅读会话；退出/后台立即结算；子页错误重新续载；剩余子页不提前计 100%               |
| 阅读      | 滚动正文进入灵动岛、叠在常驻章节栏与页脚上                                | 限制滚动视口到正文区域，保留安全区与进度栏空间                                                       |
| 阅读      | 长单段预分页阻塞取消；后台仍累计时长                                      | 预分页按字符分片并可取消；隐藏/后台暂停时长，恢复后重设基线                                          |

## 模拟器实际体验

1. 搜索 `《凡人 修仙传》`：先出现明智屋候选，继续搜索后出现其他书源候选（合计 4 本）；结果可在继续搜索期间点击加入书架。
2. 明智屋在本次网络环境中连接超时，旧逻辑经历代理和 WebView 多重回退；最终代码在 45 秒解析上限后提示超时，保留 4 个结果并恢复搜索和加书按钮；该链路不能作为在线入库成功证据。
3. 原创 `模拟器阅读验证.txt`（49 KB，约 1.8 万字）通过 iOS Files 选择器导入，详情显示 3 章和完整正文数量。原有书籍及其 3% 阅读进度保留。
4. 分页正文显示中文/英文/𠮷/😀；右侧点击由第 1 页到第 2 页，页面首尾文字衔接；字号 20→21 重新分页后留在原阅读段落附近。
5. 切换滚动模式，复现并修复安全区/页脚重叠；退出后继续阅读恢复到第 1 章第 2 段附近。目录跳转第 2 章从章首进入。
6. 恢复字号 20/左右翻页，进入第 2 章第 2 页；切后台后终止并重启，书架保留 36% 进度，继续阅读恢复到第 2 章第 2 页。

## 当前验证边界

- 外部明智屋连接超时；未证明所有线上书源可以稳定导入或完整缓存。网络可用性仍取决于站点与代理。
- 手势拖动自动化未稳定触发原生滚动，故不计入手势验收通过；点击翻页、目录跳转、设置和续读是实际通过的路径。
- 未做真机、全部下载字体/横屏尺寸组合或 FPS 性能验收。原生分页仍使用字体宽度估算，并非逐字原生测量。
- Hermes 环境没有 GB18030 解码器时，GBK TXT 会明确提示转 UTF-8；UTF-8/UTF-16 已修复并测试。
- 模拟器保留原创测试书供复查；原有书籍未被删除或改动阅读位置。
