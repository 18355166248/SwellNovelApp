## 已修复的问题

1. 可见 WebView 的目录识别脚本包含未双写的正则反斜杠，生成后会出现 `replace(//$/, '')`，整段脚本语法错误。修正转义，并对最终注入字符串执行语法及回传测试。
2. DOM 识别原来只接受“第 N 章”和 40 字以内标题，漏掉目标书的 4 条公告/感言和 1 条较长标题。已知四个站点改按同书正文路由判断，保留公告及长标题，拒绝其他书、站外广告和导航；HTML 与 DOM 使用相同路由定义。镜像、miread/mzwread 别名按同书同章身份去重。
3. 目录分页链接按 DOM 出现顺序可能为“下一页、尾页、其余页”，从中间页导入还会把中间页放到最前。现在在同一分页模板内按页码合并，也把当前页放回对应位置。
4. 后续分页重复返回首页，原来只要非空便算成功。现在需要产生新章节，否则重试，仍失败则阻止残目录入库。明智屋同时检查分段清单是否缺少中间范围，以及重复分段、跨镜像同章重复，保留感言/序章/带空格章名。
5. 搜索书源列表原来等待所有站点结束，慢站超时会让已完成的快站候选一起丢失。现在逐站回传结果，搜索结束后忽略迟到回调；本轮真实网络在约 1.2 秒保留了笔趣阁候选。
6. 正文加载时另有一个 40 字标题上限，会把正常长目录标题变为“章节”。调整为与目录识别一致的 200 字上限，并验证加载、缓存后的标题保持原样。
