# 第三方网页广告与遮挡净化

2026-10-08，承接[网站首页搜索验证](./browser-import.md)。此处记录可见内置浏览器的净化，不把隐藏抓取成功当作原生页面交互通过。

## 实际原因与处理

1. 原来的通用过滤只处理带文字的推广外链。笔趣阁详情页实测仍有成人影视横幅，无文字的图片广告没有命中。
2. 站点 `/config/v7.js` 的公开脚本包含透明固定点击网格、底部占位样式与触摸后外域跳转。现隐藏透明点击层、已知广告载体、外链媒体与站内中转宽幅图，保留封面、Logo、搜索和书籍/章节链接；前一轮四站跨域导航拦截继续生效。
3. 搜索结果页还有另一种广告：原生页面诊断确认随机 class 的空 `DIV` 固定在底部，大小约 **402 × 121**，普通 DOM 子元素、文字、背景图都为空。新增对小说站宽幅空固定宿主的隐藏，包含宿主点击区域；不依赖其封闭内容能否被遍历。封闭 shadow DOM 用例单独回归，不将其内部实现当作站点已证实事实。
4. 在页面内容加载前安装同一套脚本，后续监听新节点、图片加载及属性替换；广告脚本重设显示样式时恢复隐藏。MutationObserver 合并变化，仅扫描变化的子树，移除原来的周期性全页扫描。1500 章节的用例验证修改单张广告不会重新扫描整个文档。
5. 阻止广告新窗口和外部 App 协议。普通新窗口链接、站内搜索表单转为当前页；真实点击触发的同站 `window.open` 仍允许在当前页打开。保留验证码容器和已知验证 iframe，不绕过验证。

脚本抽至 `src/services/browserFetch/pageSanitizer.ts`，可见 WebView 的加载前/加载后注入均使用同一版本。临时页面结构诊断已从最终代码移除。

## 验证

- JSDOM 执行真实注入字符串，覆盖图片广告、站内中转横幅、透明网格、随机空浮层、封闭 shadow DOM、动态插入/延迟填充/重写样式、搜索表单、验证码、长目录、书名含敏感词的合法封面、正常新窗口链接等。
- 全部 **64 个测试套件 / 424 项测试通过**；TypeScript 通过；相关文件 ESLint 无 error，Screen 既有 9 条 warning 保留。
- iOS Release 和 Web 生产构建、最终原生交互结果见完成记录。

## 边界

基于节点、链接、布局和已确认站点结构净化，没有对所有图片进行内容审核，不能保证所有未知站点及后续更换广告样式都能识别。外部广告资源可能仍发起网络请求，此次并未实现系统网络层广告拦截。明智屋和玄幻阁上一轮的上游可达性问题仍不能用其他站点通过替代验收。书架数据与用户已有章节缓存不做删除。
