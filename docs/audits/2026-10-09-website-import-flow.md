# 网站加入书架与更新流程审计

## 本轮发现与修复

1. **详情页的最新章节可能被当整本目录。** DOM/HTML 提取器现在共用明确目录入口发现；导入先验证同站同书的完整目录入口，再聚合所有分页。玄幻阁详情路由也统一走此流程。若入口跨站、书名不符或任一分页失败，停止入库并保留可重试预览。
2. **连点与离页缺少完整控制。** 加入按钮同步锁定；换页、返回或卸载取消分页与资料抓取。旧任务不能解除新任务的锁、覆盖新页提示或迟到跳详情。已进入持久化事务的导入完成发布，避免磁盘成功、界面却报失败。
3. **网页导入书籍的更新能力割裂。** 已注册网站入库保留注册源身份；旧 host 身份也能按来源地址找回更新适配器。未注册网站复用同一通用提取/分页流程检查更新，详情页提供检查更新与追更入口；尚无专用全本下载能力时明确显示“阅读时缓存”。
4. **追更按数组长度截取。** 远端目录先去重，再按来源身份合并。等长重排、标题更正和中间插章都会同步；缓存、当前章、阅读器索引、历史和书签按稳定身份迁移。玄幻阁手机/旧 read 路由视为同章，章内进度未懒加载时从已保存百分比保留比例。
5. **更新未落盘就显示成功。** 导入和更新共用事务发布队列；保存失败向调用方抛错，旧目录与未读数不变。同书手动/自动检查共用请求，取消一个使用者不误杀另一个。保存期间新缓存/阅读状态重新合并，迟到请求不复活被移除书籍。
6. **残目录误报最新。** 更新若缺少旧章节，保守拒绝并提示不完整，保留阅读数据；原 bookshuku 残目录修复仍走原有完整性门槛。更长但缺旧章的重新导入也不能覆盖原书。原站确实删章时需要用户核对，当前不会自动认定为合法删除。
7. **新章自动缓存错位及部分失败被掩盖。** 按新增来源身份定位，中间插章不再错误缓存原目录末尾 N 章。只有落盘成功才计入缓存成功数；检查/缓存部分失败会与更新成功一起展示，避免误报全部完成。
8. **展示兼容分支回写占位封面。** 共享提取器拒绝占位图后，OG 兼容分支不能重新写回；旧页错误消息也必须带页面地址并通过当前页面校验。玄幻阁注册导入保留简介。详情页清除无效 Image.pointerEvents 类型属性，类型检查现已通过。
9. **搜索结果与链接导入走不同流程。** 原生搜索中需要网页导入的书源统一先打开网页预览；避免玄幻阁大目录被直接导入的 45 秒超时打断。已有书籍仍直接进入原书详情。
10. **长书已读但显示未开始。** 阅读百分比为 0% 时，依据已保存的当前章和阅读时间展示“阅读中”和“继续阅读”；检查失败时展示具体原因并提供回到原网页的恢复入口。

## 可重复执行的自动化

```sh
npm run test:website-flow
npm run check
```

已有 CI 会在 push / pull_request 执行 `npm run check`，新增用例会自动纳入。启动/构建原生包、Web 和真机安装前会生成共享网页资料脚本，回归仍检查生成文件和 TS 提取器一致。

- `websiteImportFlow.test.ts`：仅替换网页传输与存储边界，真实运行 DOM 注入、完整目录发现、分页、入库去重、注册适配器正文抓取、重启懒加载、插章更新；另测未知站点、取消、跨书/跨站拒绝与 OG 占位图。
- `InAppBrowserScreen.test.tsx`：真实页面的同步防连点、离页取消、旧页错误隔离、失败保留预览与重试、成功导航。
- `SearchScreen.import.test.tsx`：网页导入/直接导入分流与已有书籍复用；`followResult.test.ts`：部分失败提示；详情页交互回归验证 0% 续读及更新失败后的原网页入口。
- `onlineBookImport.test.ts`：插章/等长重排、去重、残目录、存储失败重试、共享更新、独立取消、删除竞争、保存期间新缓存、插章缓存、重新导入防覆盖等。
- 既有目录解析矩阵、RN URL 环境、书签/阅读引用迁移、持久化、封面补全和详情交互继续纳入回归。

本地 `npm run check`：76 套件、522 项通过；TypeScript 通过；ESLint 0 errors（188 条现有风格等警告）；Web production 构建通过（两条包体积提示）；版本一致性、diff check 通过。最后补充详情页失败恢复断言后，`npm run test:website-flow` 再次执行 12 套件、99 项通过，类型检查通过。测试中的本地页面与内存存储矩阵不等于真实网站/设备网络验收。

## 原生验收

本轮最终 Release 已构建并覆盖安装到“江测试机”（iPhone 12 Pro Max，iOS 18.7.8），保留原书架与阅读进度。通过 iPhone 镜像实际操作验证：

- 玄幻阁《仙工开物》详情页识别出封面、作者与最新 16 项；点击 App 加入书架后出现逐页进度（实见 15/29），最终得到 1165 个目录项。
- 详情、章节目录、正文加载与翻页连贯；第 2 章正文阅读到 2/15 页，首次返回显示 3474 已缓存字数、1/1165 项缓存。
- 点击检查更新显示忙碌状态，约一分钟后返回“已是最新章节”，目录及正文缓存保留，继续阅读恢复原章内位置。
- 最终包覆盖安装并自动启动后，两本书与封面仍保留；《仙工开物》显示“阅读中”、0%、“继续阅读 · 第 2 章：宁拙”。此时后台预取累计 8725 字、3/1165 项缓存，继续阅读仍为第 2 章原来的 2/15 页。

真实网站新增章、断网及存储故障没有现场强制造出，使用自动化边界故障测试覆盖；未知网站使用本地页面测试覆盖，不据此声称全部线上网站已逐一验收。

## 边界

站点改版、限流、验证页和网络不可达仍可能导致失败；当前保证失败可见、可重试且不覆盖已确认的本地阅读数据。原站占位封面继续明确说明，不以随机图片冒充。未注册网站必须提供可识别的章节和目录入口；需要特殊结构时沿书源/通用扩展点增加规则与对应回归。
