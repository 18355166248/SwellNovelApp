# 本地《捞尸人》加载返回专项修复

## 上次修复遗漏的环节

用户明确复现路径：书架打开本地《捞尸人》，详情仍显示“章节加载中”时返回，再点其它 Tab 不响应。

此前主要验证在线慢请求取消，没有覆盖真实本地大文件。旧路径是 `RNFS.readFile(path, 'utf8')` → RNFS 内部 `utf8.decode(base64.decode(...))` → 应用取消检查 → 整本 `JSON.parse`。取消检查发生在同步解码之后，JS 线程被占用时，返回与 Tab 点击本身也无法及时处理。

真实章节文件 `local-1782984375406.json` 为 10020789 字节、331 章；原文件 SHA-256 为 `8588ff808ce3f0f6eeb78fc48289402b2f58cbbb23056732b59f1b309980b417`。

## 修改

- 每次最多读取 32KB Base64，在解码前检查取消；块间通过定时器真正让出事件循环。
- 严格 UTF-8 解码保留跨块尾字节，兼容中文、扩展字符、正文内 BOM 和 JSON 转义。
- 流式识别章节对象边界，逐章交给标准 JSON 解析器；只有整个数组完整校验成功才发布，不返回损坏文件的部分章节。
- 其它书的缓存变更不再重新启动本书读取。
- 兼容现有章节 JSON，不迁移或重写原文件。
- RNFS 2.20.0 的 iOS `read` 方法把长度和位置声明为 `NSInteger *`，RN 新架构互操作层不支持该参数类型。修正为数值 `NSInteger`，并及时关闭每块文件句柄；补丁保存至 `patches/react-native-fs+2.20.0.patch`，由既有 postinstall 应用。

## 验证

- TypeScript 通过；62 套测试、372 项测试通过。
- 新增任意 JSON 切块边界、跨字节 UTF-8、损坏和截断文件、块间取消回归。
- 使用真实 10020789 字节文件执行分块读取，共读取 306 块，331 章所有字段与标准整本解析结果完全一致。此项是内容一致性验证，不代替原生性能验证。
- 修改文件 ESLint 无错误，decodeText 既有 17 个位运算警告仍存在；差异空白检查通过。
- Web 生产构建通过，保留两个包体积警告。
- iOS Release 构建成功，包含 RNFS 原生补丁；补丁逆向应用检查通过，并可由 patch-package 解析。

### 最终版本原生交互

iPhone 17 Pro / iOS 26.2 模拟器，使用原有本地书籍，未使用在线慢请求测试书：

1. 打开《捞尸人》并等待完整加载，详情显示“331 章”“已缓存正文约 336.3 万 字”。
2. 点击原有“继续阅读第 10 章”，阅读器显示原章节“第 9 章”和“本章 3 / 45 页”。目录索引与章节标题属于原数据，不在本次重编号。
3. 恢复验证前阅读元数据并冷启动，确保章节未在内存命中；打开详情，明确观察到“0 章”“章节加载中”，点击底部返回，随后立即切换“搜书”，对应页面正常显示。接着“我的”“发现”也可正常切换。
4. 再次打开仍未加载到内存的《捞尸人》，在“章节加载中”点击顶部返回，随即点击“我的”，页面正常显示。
5. 原章节文件 SHA-256 保持不变；阅读进度恢复至验证前状态，原有 6 本书保留。

中间验证曾发现新读取接口不能完成加载，修正 RNFS 原生参数后，以上完整加载与两轮返回流程才作为最终通过证据。仅验证菜单可点不代表整本加载成功。

## 使用与边界

原生补丁必须重新编译安装 iOS 应用；仅刷新 JS 无法修复 RNFS 原生接口。模拟器已安装新 Release 版本，用户真机表现尚未验证。本次没有量化触摸延迟或宣称所有大书性能问题均已消除；单章对象最终仍使用同步 JSON 解析。
