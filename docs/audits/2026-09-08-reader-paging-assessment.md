# 阅读器翻页评估与第一轮修复

日期：2026-09-08。代码通过 `git pull --ff-only` 从 `47db724` 更新到 `615eb24`，拉取前工作区干净。本报告记录基于该版本完成的第一轮修复与验证。

## 结论

阅读器已经具备字符偏移保位、分页缓存、相邻章预加载和原生跨章保护。本次补齐了连续输入、异步加载落点、旧事件隔离和 Web 翻页交互中的缺陷。自动化验证通过，但原生正文仍按字宽表估算分页，因此不能据此承诺所有字体、设备都不会截字，也没有真机帧率数据证明始终流畅。

下一轮优先做原生分页精度与真机验证，其次做跨章连续动画和超长章计算分片。

## 已修复

| 场景 | 原问题 | 本次行为 |
| --- | --- | --- |
| 同一批快速连点/按键 | 使用 React 尚未提交的旧页码，可能吞掉操作 | 以同步页码 ref 累加；拒绝旧动画的非目标落点 |
| 返回未缓存的上一章 | 加载前就消费落点，返回后落在首页 | 等正文可用后落末页，加载失败后重试也保留方向 |
| 换章、切字体和重排版 | 旧列表的滚动/可见回调可能覆盖新页码 | 回调核对章节、正文和完整排版会话；目标页至少 95% 可见后开放交互 |
| 最后一章还有网页子页 | 原生跨章判断受总章节数限制，可能无法通过滑动续载 | 先加载本章剩余内容，保留旧正文末尾偏移，并同步防止重复加载 |
| Web 章内翻页 | 强制即时跳转；旧 rAF 可能回写上次目标 | 使用可取消的 180ms 动画，结束精确落页，支持减少动态效果 |
| Web 首尾触摸跨章 | 没有越界滚动量，且右滑可能触发浏览器后退 | 识别从边界出发的水平向外滑动；拦截对应浏览器手势，单次只跨一章 |
| 用户拖动打断程序翻页 | 旧计时器可能吞掉新滚动的页码同步 | 取消旧动画和计时器，再按实际位置继续 |
| 搜索/摘抄输入与空格快捷键 | 空格和方向键被翻页监听截获，焦点页面也有重复处理风险 | 输入、浮层、组合输入和系统快捷键不翻页；正文快捷键只处理一次 |
| 跳转章首页书签 | 页码变为首页，但容器未滚回 0 | 首页与其他书签落点统一补位 |

## 仍需完善的功能

| 优先级 | 项目与证据 | 建议实现及验收 |
| --- | --- | --- |
| P0 | **原生分页精度**：`src/utils/charWidth.ts` 忽略字体族，ASCII 字符按统一宽度估算；正文渲染又移除分页器换行并重新排版。实际换行数可能与估算不同。 | 使用原生排版测量或限定范围的可见页校准；字体、系统文字缩放、字号、行距与渲染保持一致。逐页验收正文不越界、文字重建完全一致、页首偏移单调。避免恢复整章隐藏 Text 测量造成首屏阻塞。 |
| P1 | **跨章连续视觉效果**：仍按单章 FlatList 重建，并有 32ms loading 提交等待；本次解决落点和手势，跨章尚未形成连续滑动的两页画面。 | 对已缓存相邻章预备目标首/末页，统一过渡到新章；网络未就绪时保留当前页并展示等待/重试。先做平移或覆盖效果，再考虑仿真翻页。验收快速正反向操作无白帧、无跳章。 |
| P1 | **超长章与低端机顺滑性**：前台 `breakLines` 同步运行；`breakLinesCooperatively` 按段落分片，一整段很长时仍会长时间占用线程。 | 按字符数或时间预算切片，支持取消；Web 可评估 Worker，原生结合测量缓存。用十万字单段与普通多段章节测量首屏耗时、最长 JS 任务和交互延迟。 |
| P1 | **原生手势与性能验收**：组件测试可验证状态，但无法替代 iOS/Android 的回弹、速度方向、系统返回手势及真实掉帧表现。 | 真机覆盖快甩、慢拖、拖动取消、反向打断、跨章失败重试、后台恢复和横竖屏。记录 60Hz/120Hz 设备帧耗时及空白帧；目前未采集这些指标。 |
| P2 | **滚动/分页模式切换的精确保位**：滚动模式使用章内字符比例换算像素，长段、标题占位或字号变化时可能偏离原文字。 | 用可见段落和段内偏移作为滚动锚点，与分页字符偏移统一，验收来回切换不逐次漂移。 |
| P2 | **构建体积与维护成本**：生产入口约 926 KiB，超过当前 800 KiB 提示阈值；ReaderScreen 超过 4,000 行。 | 阅读器按分页控制、正文呈现和设置/目录拆分；按路由延迟加载非首屏模块。本次新增 Web 手势已独立为 hook。 |

- `npm run check`：版本一致性、TypeScript、ESLint、Jest、Web 生产构建均通过。47 个测试套件、223 个测试。ESLint 有 183 条警告、0 个错误；Webpack 有入口体积相关警告。
- 新增组件回归：同批连续三次翻页及旧动画回调、未缓存上一章加载后落末页、失败重试仍落末页、末章网页子页仅加载一次且定位到追加正文、排版更新后的旧可见回调隔离和字符锚点保留。
- Chrome 无头浏览器使用独立测试书库与真实触摸事件，逐页读取 25 页混合中文、英文、生僻字与 emoji 的正文，重建文本与原文完全一致；正文块无页底溢出。另验证动画中间帧与落点、双向触摸跨章、同批三次按键、输入框空格/方向键、首页书签、正文焦点下空格/Shift+空格、字号及横竖屏重排。
- 浏览器脚本：`scripts/verify-reader-web.cjs`；结果及截图：`artifacts/reader-qa/`。浏览器结论只覆盖这组样本和 Chrome，不代表所有字体或浏览器都已通过。
- 没有连接 iOS/Android 真机，没有执行原生构建，也没有测试真实外部书源。加载失败和延迟场景由组件测试模拟。

复跑浏览器测试：先启动 Web 开发服务器，再使 `playwright` 可被 Node 解析，运行 `node scripts/verify-reader-web.cjs`。默认连接 `http://localhost:8093` 并使用已安装的 Chrome；可通过 `READER_QA_URL` 和 `READER_QA_BROWSER` 修改。测试使用独立浏览器上下文，不写入日常浏览器的书库。
