## 结论

第二轮仍不建议整体换视觉。深绿背景、宋体标题、低饱和强调色和窄屏居中阅读容器在书架、我的、设置与阅读足迹之间保持一致，问题主要出在信息优先级和交互承诺：发现页把十余条推荐放在续读之前，同一本书又同时出现在“最近在读/最近加入”；部分视觉上可点击的行在 Web 语义树中仍是 generic；危险操作与自动备份还有跨端行为断点。

本轮按现有设计体系完成了信息架构与交互升级，没有新增一套视觉语言。

## 已落地改造

### 发现页

- “继续阅读”移动到推荐之前，过滤已读完书籍、限制 3 本，并直接进入阅读器，不再先绕到详情页。
- 推荐首批限制为 5 本；右上角操作在已有数据时切换下一批，不再反复请求同一书源首页。
- 保留“查看全部/收起”入口，既降低首屏长度，也不隐藏完整列表。
- 推荐来源按实际结果生成，单个来源失败时不再固定声称两个来源均成功。
- 推荐项增加“加入/已在书架/加入中”语义、忙碌和禁用状态；空结果提供明确重新获取。
- “最近加入”排除已经在续读或追更区出现的书，减少同页重复。

### 跨端交互与可访问性

- 搜索、书架和设置 ScrollView 使用 `keyboardShouldPersistTaps="handled"`，输入框聚焦时搜索、筛选和表单按钮无需先点一次收键盘。
- 书架多选时隐藏视图切换，标题区域允许收缩，降低 320px 窄屏头部溢出风险。
- 设置、缓存、回收站与阅读足迹的返回/菜单/危险操作补充按钮角色、可读标签、禁用状态和 44px 级核心触控高度。
- Reader Web 不再全局移除所有后代焦点轮廓，可操作元素恢复 `:focus-visible`。
- 长章节名和长书名在分页首屏按单行省略，防止渲染高度超过分页器预留预算；字号到达 16/40 上下限时按钮明确禁用。
- 滚动模式在换章、正文替换或字号变化时按测量 key 重挂载容器，确保新内容重新提交视口/正文高度并恢复续读位置。

### 数据安全与状态可信度

- 缓存清空、彻底删除和清空回收站统一使用跨端确认；RN Web 不再因 `Alert.alert` 回调缺失而点击无效。
- 永久删除先等待章节文件删除成功，再更新书库状态；失败时保留回收站记录并给出重试提示，不再先显示成功。
- 批量永久删除按单本成功结果收敛：正文已清除的条目同步移除，失败条目继续留在回收站；恢复提交后的旧缓存清理失败不再把整次恢复误报为失败。
- 缓存统计逐本容错：单本读取失败时保留其余书籍统计，并提供“重试”，不再同时显示失败与假空态。
- 缓存占用纳入回收站在线书，避免书移入回收站后占用突然显示为 0。
- WebDAV“立即备份”成功后保存连接配置；自动备份的翻页/切章事件只负责触发检查，真正上传仍须满足连续阅读 10 分钟。

## 尚未完成的高风险项

1. 备份“替换恢复”仍直接覆盖相同 bookId 的章节文件。异常中断或多文件写入中途失败时缺少完整事务/回滚；需要单独设计 staging、commit 与启动恢复机制后再改，不能用一层提示冒充原子性。
2. 原生 VoiceOver/TalkBack、200% 动态字体、320px 真机与软键盘遮挡仍未做设备级验收。年度热力图是高密度控件，代码语义改善不等于实际触控和朗读体验已经合格。
3. Discover 数据仍只有标题、作者、来源和 URL。若后续希望升级成封面卡片、题材推荐或个性化流，需要先补推荐理由、分类和封面等可靠元数据，而不是先做更重的视觉卡片。

## 最终判断

小说页面不需要整体重新设计；需要持续升级的是任务优先级、状态真实性和跨端交互。本轮已经把最明显的发现页信息架构、键盘/窄屏交互、危险操作和备份承诺问题落到代码。下一阶段应优先解决备份替换的事务安全，并在 iOS/Android 真机完成无障碍与极端字号验收。
