# iOS 书籍加载中返回后的交互修复

## 原因与范围

- 阅读器之前只忽略迟到回调，正文请求、隐藏 WebView 及书源回退仍继续运行，占用共享抓取队列；预取和预排版也未按页面焦点停止。
- 章节文件读完后先执行整本 JSON 解析，再由 hook 检查是否已经离开。模拟器现有本地书包含约 10MB 的章节文件。
- 正文加载时未挂载正文点击区，而阅读工具栏默认隐藏，缺少明确的返回入口。

## 实现

- 详情页和阅读器按书籍及焦点创建取消会话，监听原生返回、失焦和卸载；重新进入创建新会话。
- 取消传递至正文、续页、目录修复、手动目录更新、整本缓存、HTTP、浏览器桥及书源回退。正常取消不作为加载错误继续重试。
- HTTP 中止传输及响应体等待；隐藏 WebView 移除队列任务、停止当前导航并重建网页运行环境，迟到事件不能影响下一个任务。
- 共享正文请求按订阅者计数，最后一个调用者离开才中止底层请求；取消后立即移除共享项，重新打开可以重新请求。
- 本地章节在读盘完成后、JSON 解析前检查取消；返回后停止预取和相邻章节预排版。
- 加载中显示“取消加载并返回”，失败页提供返回入口。详情页缓存计数按章节变化重新计算，避免按钮状态更新重复扫描正文。

## 验证

- TypeScript 通过；60 个测试套件、353 项测试通过，包括返回过渡即取消、迟到结果不写缓存、重新请求、共享请求取消、WebView 释放队首、取消读盘后不解析 JSON、HTTP 取消后不回退。
- 修改文件 ESLint 无错误；原有内联样式等警告仍存在。`git diff --check` 通过。
- Web 生产构建通过，保留两个包体积警告。
- iPhone 17 Pro / iOS 26.2 模拟器 Release 构建成功并安装。

### 原生交互证据

在本机 `127.0.0.1:38471` 设置正文延迟 120 秒的临时书籍，另设立即返回正文的书籍：

1. 慢正文在 `07:55:42.591 UTC` 开始请求；仍显示“正在准备章节…”时点击“取消加载并返回”，请求在 `07:55:47.390 UTC` 关闭，未发送正文，早于浏览器请求超时。
2. 返回书架后“我的”“搜书”均正常显示对应页面。
3. 另一册书的正文请求于 `07:56:13.581 UTC` 发起，55ms 后服务端发送；阅读器随后显示正文及“本章 1 / 38 页”。原生浏览器仍保留既有注入等待，不以服务端耗时推断屏幕加载耗时。
4. 退出应用检查：取消书籍缓存正文长度为 0；后续书籍缓存正文长度为 12011。
5. 验证结束恢复原元数据、移除两册临时测试书籍，模拟器书架恢复原有 6 本书；本机测试服务已停止。

构建记录：`/tmp/swell-cancel-ios-build.log`；测试服务请求记录：`/tmp/swell-cancel-qa-http.log`。

## 验收边界

- 原生文件读取不能中途停止；已经开始的同步 JSON 解析也不能被中途打断。本次阻止页面离开后才到达的文件继续解析。
- 保留已经完成并发布的有效缓存；未把用户退出当作缓存删除。
- 以上为可控慢请求的模拟器交互证据，尚未验证用户真机、全部外部书源或量化卡顿改善幅度。
